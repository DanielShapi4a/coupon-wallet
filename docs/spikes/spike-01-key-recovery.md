# ניסוי טכני 01: שחזור מפתחות

- **עודכן:** 2026-10-10.
- **מצב:** בביצוע.
- **`branch`:** `spike/key-recovery`.
- **קוד:** `spikes/key-recovery`. זה קוד זמני, והוא לא עובר ל־`main`. רק המסמך הזה והמסקנות עוברים.
- **מסמכים קשורים:** [ADR-001](../adr/ADR-001-key-management.md), [architecture.md](../architecture.md).

## מה בודקים, לפי סדר עדיפות

- **שאלה 1, הצפנה:** האם `react-native-libsodium` עובד ב־`Expo` על `Android`? בודקים:
  - `XChaCha20-Poly1305` עם `AAD`.
  - גזירת מפתחות.
  - זוג מפתחות `Ed25519` שנגזר ממפתח הכספת.
- **שאלה 2, `passkey` עם `PRF`:**
  - האם אפשר ליצור `passkey` עם הרחבת `PRF`, דרך `react-native-passkeys` ומנהל הסיסמאות של `Google`?
  - האם הפלט של `PRF` זהה בין הפעלות, וגם אחרי שמסירים את האפליקציה ומתקינים אותה מחדש?
- **שאלה 3, `Block Store`:** לא נבדק בשלב הראשון. דורש מודול `Kotlin`, ולכן נכנס לשלב 2 של הניסוי. נבדוק בו:
  - שמירה וקריאה.
  - האם הגיבוי מוצפן מקצה לקצה.
  - האם המפתח שורד הסרה של האפליקציה והתקנה מחדש.
- **שאלה 4, `expo-secure-store`:** מה קורה למפתח הכספת אחרי הסרה והתקנה מחדש. הצפי הוא שהוא נמחק.

**מחוץ לניסוי הזה: התראות `FCM` בלי תוכן.** הן לא קשורות לשאלת השחזור, ודורשות פרויקט `Firebase`. הן ייבדקו בניסוי 02, לפני שמממשים את התזכורות.

## קריטריוני הצלחה

- **שאלה 1:**
  - כל הבדיקות עוברות.
  - פענוח עם `AAD` שגוי, או של `ciphertext` ששונה, נכשל.
- **שאלה 2:** הפלט של `PRF` זהה לפני ואחרי התקנה מחדש. אם כן, `passkey` הוא העטיפה הראשית ב־`ADR-001`.
- **שאלה 3:**
  - אחרי התקנה מחדש, הקריאה מחזירה את המפתח.
  - במכשיר נעול, הגיבוי מדווח כמוצפן מקצה לקצה.
- **שאלה 4:** ההתנהגות מתועדת.

## איך בונים

- **`development build` של `Expo`:** `Expo Go` לא מספיק, כי יש קוד `native`.
- **בנייה בענן, ב־`EAS Build`:** לא צריך `Android SDK` במחשב. במחשב הזה אין `Android SDK`, וגרסת ה־`Java` היא 8, שלא מתאימה לבנייה מקומית.
- **בטלפון:** מתקינים את קובץ ה־`APK`. ‏`Metro` רץ במחשב ומגיש את ה־`JavaScript`, כך ששינויים ב־`JavaScript` לא דורשים בנייה מחדש.

## מה צריך ממך

- **חשבון `Expo`:** חינמי. ההתחברות נעשית במחשב שלך.
- **טלפון `Android`:**
  - אישור להתקין אפליקציות ממקורות לא מוכרים.
  - חיבור לאותה רשת `Wi-Fi` כמו המחשב.
- **לשאלה 2, אישור לפרסום קובץ `assetlinks.json` ב־`GitHub Pages`:**
  - הכתובת: `danielshapi4a.github.io`. זה דורש `repo` ציבורי בשם הזה.
  - הקובץ כולל רק את שם החבילה ואת טביעת האצבע של מפתח החתימה, כלומר אין בו סוד.
  - הוא מוכיח ל־`Android` שהאפליקציה רשאית ליצור `passkey` עבור הדומיין.

## מה כבר מוכן

- **פרויקט `Expo` (`SDK 57`)** ב־`spikes/key-recovery`, עם הספריות `react-native-libsodium`, `react-native-passkeys`, `expo-secure-store` ו־`expo-dev-client`.
- **מסך אחד עם כפתור לכל בדיקה.** כל כפתור מדפיס `PASS` או `FAIL`.
- **בדיקה מקדימה:** ה־`typecheck` עובר. `expo-doctor` מזהיר שהספרייה `react-native-libsodium` לא נבדקה על `New Architecture`, וזו בדיוק אחת השאלות שהניסוי בודק.
- **ממצא מוקדם מהקוד:**
  - `HKDF-SHA256` זמין בספרייה, אבל רק תחת שם שמתחיל ב־`_unstable`.
  - `crypto_kdf` היציב דורש מפתח של 256 ביט.
  - ההחלטה בין השניים תתקבל לפי תוצאות הניסוי.

## שלבי ביצוע

**שלב 1: בנייה והתקנה.** המשתמש מבצע את ההתחברות, כי היא דורשת את פרטי הגישה שלו:

```bash
cd C:\git\coupon-wallet\spikes\key-recovery
```

```bash
npx eas-cli login
```

```bash
npx eas-cli init
```

```bash
npx eas-cli build --profile development --platform android
```

- **מפתח חתימה:** בבנייה הראשונה, `EAS` שואל אם ליצור מפתח חתימה. עונים כן.
- **התקנה:** בסוף הבנייה מתקבל קישור או קוד `QR` לקובץ `APK`, ומתקינים אותו בטלפון.
- **הרצה:** במחשב מריצים `npx expo start`, ובטלפון פותחים את האפליקציה ומתחברים לשרת הפיתוח. הטלפון והמחשב צריכים להיות באותה רשת.

**שלב 2: בדיקות 1 ו־4.** הכפתורים 1, 2a ו־2b. אחר כך מסירים את האפליקציה, מתקינים אותה מחדש, ומריצים שוב את 2b.

**שלב 3: בדיקה 2.** צריך לפרסם קובץ `assetlinks.json` בכתובת `https://danielshapi4a.github.io/.well-known/assetlinks.json`.
- **טביעת האצבע:** את ה־`SHA-256` של מפתח החתימה מקבלים מהפקודה `npx eas-cli credentials`.
- **ב־`GitHub Pages`:** צריך גם קובץ `.nojekyll`, אחרת התיקייה `.well-known` לא תוגש.

```json
[
  {
    "relation": [
      "delegate_permission/common.handle_all_urls",
      "delegate_permission/common.get_login_creds"
    ],
    "target": {
      "namespace": "android_app",
      "package_name": "io.github.danielshapi4a.couponwallet.spike",
      "sha256_cert_fingerprints": ["<SHA-256 from eas credentials>"]
    }
  }
]
```

אחרי שהקובץ מפורסם: כפתור 3a, ואז 3b. רושמים את הפלט, מסירים את האפליקציה ומתקינים אותה מחדש, מריצים שוב את 3b ומשווים.
